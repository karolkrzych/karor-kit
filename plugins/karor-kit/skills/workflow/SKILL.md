# Workflow

Notes in -> landed main + playtest ask out. Sequences `refinement` (architect variant) and `batch-implement` (runner variant): same gates collapsed into ONE plan gate, one orchestrator, zero code written by it. Per-ticket contract stays the `implement` one (self-contained brief, scope is law, tests gate).

Output style: Be extremely concise. Sacrifice grammar for the sake of concision. Human sees: handoff summary, ONE plan gate (decisions + ticket table + biggest design calls), 1 line per wave, final report.

## Routing — economy, quality where it counts (Karol, 2026-09-06)
Save tokens everywhere EXCEPT where quality is decided. **Fable guards quality, never volume**: the architect (digest, rulings, bodies of rule-touching tickets), implementer of the ≤2 heaviest tickets the architect marks `fable` (novel engine seams only), the ONE final skeptic review. **Opus**: engine seams, cross-cutting / UI-state tickets, icons, per-ticket skeptic reviewer, mechanical ticket bodies written from the digest in parallel with Fable. **Sonnet**: content-as-data, cosmetics, prep, landers, bookkeeping, docs close-out. Orchestrator (Fable) never reads game sources, never writes code — briefs, prompts, reports only. `quality` arg = Fable skeptic per ticket as well; explicit `m:` labels win.

## Steps
0. **Handoff** (orchestrator, before any agent). Dir `<wt-root>/briefs-vN/`: `HANDOFF-vN.md` per `${CLAUDE_PLUGIN_ROOT}/references/workflow/HANDOFF-template.md` — mandate + routing, the human's notes VERBATIM, orchestrator reading = decisions (human-settled, never re-litigated), parking, numbered work items with what "done" means; `COMMON.md` = previous batch's + a "Batch vN" section (baseline sha + suite counts, rulings letter, digest path, session trailer). In parallel, sonnet: `LINEAR-OPEN.md` (open issues, Batch log doc). Cut `wt/arch-vN` detached at main. Copy the runner `${CLAUDE_PLUGIN_ROOT}/references/workflow/{runner.js,wave.js}` to the scratchpad; paths/session go in via args, never edited into the scripts.
1. **Architect** = ONE Fable agent in `wt/arch-vN` (read-only + throwaway experiments; must end clean). Deliverables: `DIGEST-vN.md` (inventory delta with paths, spec with exact numbers/texts/ids, rulings `<letter>1…`, engine gaps + minimal extensions, tickets/waves/file ownership, budget arithmetic, playtest risks, parking), `TICKETS.md` (table: T# | title EN | labels | priority | est | model | blockedBy | wave | slug | files; open-Linear overlap; count-pin arithmetic), `T<n>.md` for rule-touching tickets, `ICONS-vN.md`, `NOTES-T<n>.md`. Bodies of mechanical tickets (cosmetics, data audits — marked `body: opus` in the table) → opus writers in parallel from the digest. Splitting the ARCHITECT = no (conflicting rulings, file-ownership collisions); splitting the WRITING = yes. Expect ≈0.5M Fable tokens / 45–60 min: whole repo in context is the point, not a bug.
2. **Plan gate**: orchestrator reads digest + tickets critically (that IS its review — briefs, not sources). Human present → summary (decisions, biggest design calls, ticket table, cost estimate) → OK. `autonomous` / human away → proceed, every decision taken on their behalf listed in the final report.
3. **Bookkeeper** (sonnet): Linear tickets (project, labels, priority, estimate, `m:` label, blockedBy), id map into `TICKETS.md`, `KAR-NNN.md` copies of the bodies, refinement note into "[<project>] Batch log" (per `refinement` step 6).
4. **Runner** `runner.js` per wave = prep (sonnet: pull main, worktree + branch per ticket, baseline from `LEDGER.md`) → `wave.js` per ticket: implementer(model) → opus skeptic (scope + tests + refute) → one fix round + re-review → sonnet lander (push, PR, trial merge in the landing worktree, import + full suite, ff main, push) → integrate-on-conflict (merge origin/main INTO the branch, never rebase) + one reland → bookkeeper (`LANDED.md` seams/content/surprises, `LEDGER.md` row, Linear comment + Done). Stops at the first non-landed ticket → orchestrator rules: scope extension = a paragraph appended to `KAR-NNN.md` (implementers never widen scope themselves), then resume with `resume_findings` / `resume_review` and IDENTICAL args + `resumeFromRunId`.
5. **Final review**: ONE Fable skeptic, read-only on main (`wt/review-vN`): findings (severity, area, file:line, fix), playtest risks with tuning knobs, verified-OK list → `FINAL-REVIEW-vN.md` → one fix-up ticket (opus) → docs close-out (sonnet: rulings into the spec doc, decisions, plan ledger, parking) → Batch log section (per `batch-implement` step 6).
6. **Report** (PL, casual): table landed tickets + PRs, main sha, suite counts before/after, subagent token total, playtest risks + knobs, decisions taken on the human's behalf, open questions, playtest ask. Memory note for the next session. Batch closes only with the human playtest; feedback → next `workflow`.

## Rules (earned in batches v4–v6)
- Waves cut by FILE ownership, never logic alone; shared hotspots (count pins, catalogs, balance keys, run-flow tests) get ONE owner per wave. Engine seams before the content/UI that needs them; icons before content that references them.
- Pre-grant in briefs what would otherwise block a run: mechanical pin moves in flow tests, fixture-id renames on collision (`te_*`, `pb_*` prefixes), count-pin arithmetic written out, hidden-fixture mends named.
- Ticket body self-contained: implementer reads `T<n>.md` + `COMMON.md` + digest + code, nothing else. Exact numbers/texts/ids; tests table = one row per behaviour that would go red without it; UI-state matrix where states change.
- Never commit import churn (`git checkout -- game/addons game/assets game/project.godot` before commits); never rebase / force-push / reset --hard / `--no-verify`; landing serialized; PRs merged locally as `Merge pull request #N from <owner>/<branch>`, main pushed by the lander.
- Orchestrator rules on blockers, never the implementer; two failures on one ticket = ticket or architecture wrong, not the agent.
- Budget: architect ≈0.5M, one wave ≈1M, final review ≈0.35M, bookkeeping ≈0.3M (Fable-heavy batch ≈9M, economy ≈6M). Report the total.
- One batch = one session; runner resumable across context resets — run ids + args live in the memory note.
